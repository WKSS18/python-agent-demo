## 2026-09-14：本地 `/notes` 接口 500

**状态：已修复**

### 1. 问题与影响

本地前端进入知识对话页后，浏览器 Network 中 `GET /api/notes` 返回 `500 Internal Server Error`，导致顶部笔记数量和笔记列表无法正常加载。

### 2. 复现与证据

后端日志显示请求已通过鉴权并进入 `/notes` 路由，但 SQLAlchemy 查询失败：

```text
sqlite3.OperationalError: no such column: notes.source_key
SELECT notes.id, notes.title, notes.content, notes.owner_id, notes.source_key ...
```

### 3. 根因分析

代码中的 `Note` ORM 已新增内部字段 `source_key`，用于识别系统导入笔记来源并避免重复导入；但本地 SQLite 数据库仍停在 Alembic 版本 `20260811_0004`，没有执行包含该字段的迁移 `20260821_0005_add_note_source_key`。

这属于“代码版本已更新，但本地数据库 Schema 未同步”的环境问题，不是前端请求、接口代理或登录 token 的问题。

### 4. 方案与关键决策

使用项目已有 Alembic 迁移机制升级本地数据库到最新版本，而不是临时手写 SQL 补字段。这样可以保证本地库结构与迁移历史一致，后续再切到 MySQL 或生产环境时也能用同一套流程。

### 5. 修改范围

本次没有改业务代码，只执行本地数据库迁移：

```text
alembic upgrade head
```

迁移结果从 `20260811_0004` 升级到 `20260821_0005 (head)`。

### 6. 验证结果

- `/health` 返回 `200`，服务存活正常。
- `alembic current` 返回 `20260821_0005 (head)`。
- 新建临时测试账号登录后请求 `/notes`，返回：

```json
{
  "data": [],
  "code": 200,
  "message": "success"
}
```

### 7. 生产发布与回滚

本次只处理本地开发环境，没有同步生产，也没有操作生产数据库。

### 8. 边界与后续改进

- 本地启动脚本已经包含 `alembic upgrade head`，以后如果手动启动后端，也要先确认迁移已执行。
- 可以在应用启动或就绪检查中增加当前 Alembic 版本校验，提前暴露“数据库版本落后”问题，避免用户页面上才看到 500。

## 2026-08-22：RAG 引用无关笔记（CSS transform 问题）

**状态：已上线**

### 1. 问题与影响

用户询问 `transform有哪些属性`，回答正文基本正确，但系统错误引用了公务员言语题、社区招聘和入职体检笔记。错误引用会让用户误以为回答由这些资料支撑，属于 RAG 可信度问题。

### 2. 复现与证据

使用生产数据库中的原问题和用户范围运行检索诊断：

- 修复前：`accepted=true`，返回 3 条无关引用。
- 无关候选的 Dense 分很低，但稀疏分和相对归一化后的 Rerank 分异常偏高。
- Qdrant 已按 `owner_id` 隔离，问题不是跨租户数据泄漏。

### 3. 根因分析

1. 排序分使用候选集合内的相对归一化。候选很弱时，“最不差”的结果仍可能被归一成高分。
2. 只对第一条候选做整体接受判断；一旦第一条通过，前 N 条候选会全部进入引用。
3. 召回排序、模型上下文和前端引用没有明确区分“候选”与“可引用证据”。

### 4. 方案与关键决策

- 保留宽召回候选用于诊断和排序。
- 新增逐候选绝对证据门控：Dense、词法覆盖和 BM25 分别作为独立信号计算。
- 无字面依据时，必须达到更高的强语义阈值才允许引用。
- 在 `RagOutcome` 中单独维护 `evidence`，不再把全部 `candidates` 当成引用。
- 模型上下文、SSE `sources`、前端引用和历史消息快照统一使用 `evidence`。
- 无可靠证据时允许模型使用自身知识回答，但引用必须为空。

### 5. 修改范围

- `app/config.py`：增加词法和纯语义引用阈值。
- `app/rag_pipeline.py`：逐条计算绝对证据分并生成 `evidence`。
- `app/services.py`：只将 `evidence` 转换成引用快照。
- `tests/test_rag_pipeline.py`：增加截图场景、相关正例和强语义正例。
- `.env.example`、`.env.production.example`：补充可配置阈值。

### 6. 验证结果

- 本地后端测试 35 项全部通过。
- 生产原问题修复后：`accepted=false`、`reason=no_citable_evidence`、引用为空。
- 生产正向查询仍能引用准确笔记。
- API `/ready` 返回 200，API、MySQL、Qdrant 健康，近期日志无新增异常。

### 7. 生产发布与回滚

- 仅替换 API 镜像，没有重建 MySQL、Qdrant、RabbitMQ，也没有操作数据卷。
- 发布前备份目录：`/opt/fieldnote/python-agent-demo/deploy-backups/20260822-rag-citation-fix`。
- 保留旧 API 镜像回滚标签。

### 8. 边界与后续改进

- 已生成的历史回答保存的是引用快照，不会自动重算；新问题使用修复后的规则。
- 阈值需要结合持续扩充的标注集评估，不能只依赖少量人工样本。

## 2026-08-22：Vue 问题错误引用 React 和言语笔记

**状态：已上线**

### 1. 问题与影响

用户询问 `vue3介绍下`，回答引用了 `react测试` 和公务员言语笔记。Vue 与 React 属于相近技术领域，Dense 召回存在一定相似度是正常现象，但相似候选不能直接等同于可靠引用。

### 2. 复现与证据

生产修复前的关键分数：

| 候选 | Dense | BM25/稀疏 | 词法覆盖 | 最终证据分 | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| `react测试` | 0.583 | 0.931 | 0.167 | 0.514 | 错误引用 |
| 言语笔记 | 0.556 | 0.777 | 0.167 | 0.481 | 错误引用 |

词法覆盖 `0.167` 来自“下”等单字碰撞；BM25 随后放大了这个无意义信号。

### 3. 根因分析

1. 旧中文分词同时保留单字和二元组，`下、有、的` 等高频单字造成大量假重合。
2. `介绍、怎么、如何、一下` 等问法噪声被当作知识关键词。
3. Dense 能识别 Vue 和 React 都属于前端框架，但无法保证候选回答的是同一个技术对象。
4. 缺少显式技术实体一致性校验。

### 4. 方案与关键决策

- 继续使用 Dense + BM25 混合检索，但重新定义 BM25 输入词项。
- 去除常见问法噪声，不再保留中文单字，只使用有效英文技术词以及中文二、三字窗口。
- 对 `Vue3`/`Vue 3`、`React19`/`React 19` 等连写和分写形式补充归一词项。
- 增加技术实体门控，覆盖 Vue、React、Angular、Svelte、Next.js、Nuxt、Python、JavaScript、TypeScript、FastAPI、Django、Node.js、Vite、Webpack 和 Electron。
- 问题明确点名技术对象时，引用的标题或命中分块必须出现相同对象；宁可不引用，也不返回同领域但对象错误的笔记。
- Dense 保持宽召回职责，BM25 和实体门控负责提升引用精度。

### 5. 修改范围

- `app/rag.py`：改进中英文技术词分词、问法噪声过滤、技术实体识别与一致性判断。
- `app/rag_pipeline.py`：证据门控增加实体一致性校验。
- `tests/test_rag_pipeline.py`：增加 Vue/React 冲突、泛词碰撞、Vue 正例和 React 正例。

### 6. 验证结果

- 本地后端测试 39 项全部通过。
- 生产 `vue3介绍下`：
  - React 候选 Dense 仍为 `0.583`，但 BM25 和词法覆盖均降为 `0`。
  - 言语候选 Dense 仍为 `0.556`，但 BM25 和词法覆盖均降为 `0`。
  - 最终 `accepted=false`、`reason=no_citable_evidence`、引用为空。
- 生产 `react介绍下`：准确引用 `react测试`，说明系统没有简单关闭 RAG 引用。
- 公网 `/api/ready` 返回 200，API 健康，近期日志无新增异常。

### 7. 生产发布与回滚

- 生产备份目录：
  - `/opt/fieldnote/python-agent-demo/deploy-backups/20260822-rag-bm25-v2`
  - `/opt/fieldnote/python-agent-demo/deploy-backups/20260822-rag-entity-strict`
- 保留上一版 API 镜像回滚标签。
- 未修改业务数据和已有知识笔记。

### 8. 边界与后续改进

- 当前实体表针对项目常见技术栈；新增明确技术对象时应同步扩充实体规则和回归样本。
- 2 GB 单机暂不启用大型 Cross-Encoder，避免内存和延迟失控；升级资源后可评估轻量 Reranker。
- 应持续维护“相关、无关、易混淆、无答案”四类评测集，并跟踪 Recall@K、MRR 和无答案误引用率。

## 2026-08-22：Rerank 后增加 0.85 综合置信度硬门禁

**状态：已上线**

### 1. 问题与影响

单独依赖 Dense、BM25 或 Rerank 的某一个分数，无法同时表达候选的绝对相关性、排序稳定性、检索信号完整性和来源策略。即使候选逐条满足基础相关性，也可能因 Top1/Top2 过于接近而存在歧义。

目标规则明确为：最终综合置信度必须达到 `0.85` 才能关联引用；低于 `0.85` 时引用列表必须为空。

### 2. 复现与证据

构造两条几乎同分的退款审批候选：

- Top1 绝对证据分：`0.88300`
- Top2 绝对证据分：`0.88235`
- 分差归一分：`0.00433`
- 最终综合置信度：`0.83065`

候选虽然各自相关，但排序无法可靠区分，修复后的生产结果为：

```text
accepted=false
reason=citation_confidence_below_threshold
evidence=[]
```

### 3. 根因分析

1. 原有逐条证据门控主要解决明显无关内容，未将 Top1/Top2 分差纳入最终硬门禁。
2. Rerank 分数不是经过校准的概率，不能直接把 Rerank `0.85` 等同于 85% 可靠性。
3. 普通知识笔记与仓库维护资料缺少显式的来源策略区分。
4. 诊断接口没有完整返回最终置信度的组成，线上难以解释接受或拒绝原因。

### 4. 方案与关键决策

Rerank 和逐条相关性检查完成后，再计算一次查询级综合置信度：

```text
综合置信度 =
  绝对相关性 × 0.60
  + Top1/Top2 分差 × 0.15
  + 检索信号支持度 × 0.15
  + 来源策略分 × 0.10
```

各分量定义：

- **绝对相关性**：基于 Dense、有效词法覆盖和 BM25 的绝对证据分，达到 `0.60` 后饱和为 1。
- **Top1/Top2 分差**：使用绝对证据分差而非候选集相对归一分，分差达到 `0.15` 后饱和为 1。
- **检索信号支持度**：Dense 和 BM25 双路共同支持时为 `1.0`，单路支持时保守记为 `0.85`。
- **来源策略分**：仓库维护且具有 `agent-showcase:` 来源标识的资料为 `0.95`；普通用户笔记默认 `0.80`。

最终硬规则：

```text
confidence >= 0.85  -> accepted=true，允许返回通过逐条校验的 evidence
confidence < 0.85   -> accepted=false，evidence=[]
```

来源策略分是产品政策值，不是文档事实正确率。当前没有作者、域名、审核状态和签名等完整来源元数据，因此不能把它描述成事实真伪概率。

### 5. 修改范围

- `app/config.py`：增加 `RAG_CITATION_CONFIDENCE_THRESHOLD=0.85`、相关性/分差饱和参数和来源策略分。
- `app/rag_pipeline.py`：增加综合置信度计算与最终硬门禁。
- `app/schemas.py`：诊断结果增加证据分、来源策略分、是否可引用和置信度组成。
- `app/services.py`：输出可解释诊断字段。
- `.env.example`、`.env.production.example`：补充配置示例。
- `tests/test_rag_pipeline.py`：增加相近 Top1/Top2 拒绝和仓库维护来源正例。

### 6. 验证结果

- 本地后端测试 41 项全部通过。
- 小型离线集比较 `0.75/0.80/0.85`：三档结果相同，无答案误引用率均为 `0`；当前能通过基础相关性门控的正确样本综合分集中在 `0.948～0.980`。
- 生产正例：
  - `react介绍下`：综合置信度 `0.98`，准确引用 `react测试`。
  - 精确招聘问题：综合置信度 `0.98`，准确引用对应招聘文档。
- 生产负例：
  - `vue3介绍下`：无可靠证据，引用为空。
  - `transform有哪些属性`：无候选，引用为空。
  - 相近 Top1/Top2 合成样本：综合置信度 `0.83065`，低于 `0.85`，引用为空。

### 7. 生产发布与回滚

- 生产备份目录：`/opt/fieldnote/python-agent-demo/deploy-backups/20260822-rag-confidence-085`。
- 仅滚动替换 API 容器，没有操作 MySQL、Qdrant、RabbitMQ 或数据卷。
- 保留上一版 API 镜像回滚标签 `python-agent-demo-api:rollback-20260822-rag-v3`。

### 8. 边界与后续改进

- 当前离线评测集只有 10 个问题，不能把 `0.85` 解释为经过充分统计校准的概率阈值。
- 需要扩充真实问题、同义改写、多文档答案和困难负例，重点观察引用 Precision、Recall 和无答案误引用率。
- 多篇同等可靠文档可能因为 Top1/Top2 分差小被保守拒绝；未来应区分“相互冲突的近分候选”和“可共同支撑答案的近分候选”。
- 文档可信度下一步应使用显式来源元数据、人工审核状态和可追溯签名，不应长期依赖默认策略分。
