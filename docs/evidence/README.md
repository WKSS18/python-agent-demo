# 性能、RAG 与灾备证据

测试时间：2026-08-11。环境为腾讯云单机 Ubuntu，2 vCPU、2 GB RAM；结果只代表当前版本和机器，不外推为容量承诺。

## API 基线

`deploy/load_test.py` 使用标准库并发请求，不调用付费模型。

| 链路 | 请求/并发 | 成功率 | RPS | P50 | P95 | P99 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 服务器本机 -> FastAPI `/health` | 1000 / 10 | 100% | 524.60 | 17.72 ms | 22.50 ms | 37.50 ms |
| 本地电脑 -> 公网 Nginx `/api/health` | 300 / 10 | 99.67% | 13.49 | 615.62 ms | 1593.46 ms | 1882.03 ms |

公网结果混入客户端网络、运营商路径和新建 TCP 连接成本；本机结果更接近应用开销。健康接口不包含 MySQL、Embedding、Qdrant 或模型调用，不能代表 Chat 容量。下一步应分别测试 `/ready`、鉴权 CRUD、RAG 和模型 SSE，并监控 CPU/内存。

原始结果：`load-test-local-api.json`、`load-test-health.json`。

## RAG 离线评测

`deploy/rag_eval.py` 使用线上同款 `BAAI/bge-small-zh-v1.5`，当前小型集合包含 8 个知识主题、8 个有答案问题和 2 个无答案问题。

| 阈值 | Recall@3 | MRR | 无答案误引用率 |
| ---: | ---: | ---: | ---: |
| 0.45 | 1.000 | 0.9375 | 0.000 |
| 0.50 | 0.875 | 0.9375 | 0.000 |
| 0.55（线上） | 0.750 | 0.9375 | 0.000 |
| 0.60 | 0.500 | 0.9375 | 0.000 |

结论：0.55 在当前集合没有误引用，但漏掉 SSE 和 OSS 两个相关问题；降低阈值可以提高召回。本集合太小，且问题由开发者编写，不能据此直接修改生产参数。应扩展到真实用户问题，至少每个主题包含同义改写、跨段问题和困难负例，再联合评估答案忠实度。

原始结果：`rag-eval.json`、`rag-eval-0.45.json`、`rag-eval-0.50.json`、`rag-eval-0.60.json`。
